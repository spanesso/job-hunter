# Estructura y reglas de contenido del CV

Estructura validada para ATS 2026. Usar exactamente estos nombres de
sección (en el idioma del CV) para que el ATS los reconozca.

```
NOMBRE COMPLETO
[Email] | [Teléfono] | [LinkedIn URL] | [GitHub URL] | [Ciudad, País]

RESUMEN PROFESIONAL
[2-3 líneas: título + años de experiencia + stack principal + tipo de impacto]

HABILIDADES TÉCNICAS
[Lista plana agrupada por categoría: Lenguajes | Frameworks | Bases de datos | Cloud | Herramientas]

EXPERIENCIA PROFESIONAL
[Empresa] — [Título exacto del cargo]
[Mes AAAA – Mes AAAA (o Presente)]
• [Verbo de acción] + [qué hiciste] + [resultado medible]
• [Verbo de acción] + [qué hiciste] + [resultado medible]
• [Verbo de acción] + [qué hiciste] + [resultado medible]

PROYECTOS DESTACADOS
[Nombre] — [Stack usado]
• [Qué hace] + [impacto o escala]

EDUCACIÓN
[Título] — [Institución] — [Año]

CERTIFICACIONES (si aplica)
[Nombre] — [Emisor] — [Año]
```

## Reglas de contenido

- **Verbo de acción + resultado medible.** "Implementé" no "Encargado de
  implementar". Cada bullet debe cerrar con un número o un impacto
  concreto cuando exista (%, tiempo, usuarios, escala). Nunca inventes
  una métrica — si el usuario no la confirmó, deja el bullet sin número
  en vez de fabricarlo.
- **Título de cargo exacto.** Si la vacante dice "Software Engineer", el
  CV usado para esa postulación debe decir "Software Engineer", no
  "Developer" ni "Programmer" — ajustar por vacante si hace falta, sin
  mentir sobre el rol real desempeñado.
- **Keywords exactas.** "React" no "librería de JS para interfaces".
  "PostgreSQL" no "bases de datos relacionales".
- **GitHub y LinkedIn funcionales.** URLs completas, verificadas, en el
  header.
- **Summary que vende, no que describe.** Debe comunicar impacto y stack
  principal en 2-3 líneas, no ser un resumen genérico de "profesional
  con experiencia en...".
- **Fechas en un solo formato** en todo el documento: "Mes AAAA – Mes
  AAAA" o "MM/AAAA – MM/AAAA".
- **Sin imágenes, tablas ni columnas dobles** en la fuente markdown — eso
  se controla en el template HTML, no en el contenido.
